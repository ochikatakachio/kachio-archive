# KACHIO ARCHIVE

GitHub Pagesで公開する、創作作品・人物・世界観の資料集です。25作品、38人の人物プロフィール、10件の舞台・組織資料、3シリーズを収録しています。
作品の投稿先はzeta 24件、Chacha 8件、Plaitoon 2件です。「貴女だけの神様。」の表記は投稿先を問わず統一しています。「██記録室」は含めていません。

## 今回の更新

公開サイトには、作品追加・編集の入口を表示しません。以前の `manage.html` に直接アクセスしても、管理画面は出ません。以前のGitHub追加フォームは、今回のアップロード後に動く準備処理で削除します。
作者用の操作画面は、別に渡す `author-console.html` です。この公開用ZIPには含めていません。PCで開いて使い、GitHubにはアップロードしないでください。
現在のGitHub Pagesでの公開方法を保つため、公開サイト内に独自の作者ログイン画面は追加していません。公開側と、手元の作者用画面を分ける方式です。

人物紹介には、名前・読み・年齢・誕生日・身長・職業の基本情報と、容姿・性格・口調・あなた（user）との関係を表示します。公開設定で確認できなかった項目は「未設定」です。年齢から誕生日を推測したり、画像から容姿の設定を作ったりはしていません。
「裏設定」は各キャラの詳細ページに置き、通常は閉じた状態で、読者が選んで開けます。以前の創作チャットと保存済みの設定資料で確認できた35人・81項目の本文を入れています。作品ページの人物欄は画像・名前・キャラ詳細へのリンクのみで、紹介本文や裏設定を複製しません。作者用画面から本文の修正や追加もできます。
詠見・儀間勝仁・302号室の日常版の蓑島については、今回の取得で裏設定の採用本文を確認できず空欄を維持しています。公開プロフィールの来歴は残しています。未確認の秘密や別キャラの設定を補ってはいません。
口調欄に、一人称・呼び方・話し方をまとめています。「年齢・口調など、その他の設定」「さらに詳しい紹介・掲載プロフィール」「掲載プロフィールを読む」は公開画面から外しています。元資料は編集用データとして保持しています。原作版の蓑島と、302号室の日常版の蓑島は別の人物資料です。

## 公開用ZIPを上書きする

ZIPを解凍し、https://github.com/ochikatakachio/kachio-archive で「Add file」→「Upload files」を開きます。
最初に解凍したフォルダー内の `assets`、`images`、`scripts`、`.github` を入れ、「Commit changes」で保存します。続けてもう一度「Upload files」を開き、直下のHTMLやREADMEなど残りのファイルを入れて保存します。リポジトリ直下に `index.html` がある形にしてください。`assets`、`images`、`scripts`、`.github` もまとめて入れます。ZIPのまま入れるとサイトにはなりません。
`author-console.html` は、このアップロードに含めません。公開用ZIPだけを上書きしてください。
Pagesの設定は今までどおり、Settings → Pages → Deploy from a branch → `main` / `/(root)` です。

アップロード後は「Actions」で **Add archive work** を開き、`prepare-private-editor` の処理が緑になったことを確認します。この処理が、以前の公開追加フォームを外し、サイトの更新を依頼します。
この版を作成した時点では、GitHubへのアップロードと実行は行っていません。実際の公開反映と作者操作の一連の流れは、初回使用時の確認が必要です。

## 作者用の画面を開く

別ファイルの `author-console.html` をPCへダウンロードし、ダブルクリックしてブラウザーで開きます。
「作品を追加」「作品を編集」「人物を編集」「人物を追加」を切り替えられます。登録内容を更新したあとは「最新データを読み込む」を押してください。
最新データの取得に失敗した場合は、画面内にメッセージが出ます。最初に渡したデータはファイル内に残っています。編集の反映時には、対象が別の更新で変わっていないかも確認するため、古い内容で上書きはしません。

## 作品を追加する

「作品を追加」で作品URLとシリーズを指定します。zetaは作者の公開作品ページから、作品名・表紙・公開紹介・人物プロフィール・物語の導入を取り込みます。作者プロフィールのURLではなく、作品ごとのURLを使います。
Chacha・Plaitoonは、作品名と紹介文を入力します。表紙は、最後に開くGitHubの本文欄へドラッグして添付してください。
同じ作品の別の投稿先を増やす場合は、「既存の作品へ投稿先だけ追加」で対象を選びます。新規登録時に「ほかの投稿先URL」へ複数の投稿先を入れることもできます。
新しいシリーズを作る場合は「新しいシリーズ名」に入力します。追加後に最新データを読み込めば、そのシリーズを選べます。

## 登録済みの作品を編集する

「作品を編集」で作品を選ぶと、現在の内容が入力欄へ入ります。
作品名、短い紹介、概要、作品紹介、ジャンル、タグ、シリーズ、世界観、登場人物、投稿先URLを編集できます。「作品独自の設定・導入を編集する」を開くと、設定の見出しと文章、掲載時の紹介文、最初の場面も編集できます。
画像は添付しなければ維持します。表紙を変更する場合だけ、次のGitHub画面に新しい画像を添付してください。

## 登録済みの人物を編集する

「人物を編集」で人物を選び、名前・読み・年齢・誕生日・身長・職業・容姿・性格・口調・あなたとの関係を入力します。
「裏設定の項目を追加」から、見出しと本文を登録できます。追加した内容は、読者が開いて読む公開欄です。
年齢と口調は専用の入力欄から変更できます。未設定の項目は空欄のままにできます。表示を外した元の掲載プロフィールは、通常の編集で上書きしません。
人物画像を変更する場合だけ、最後のGitHub画面へ画像を添付します。既存の人物IDは変えず、登場作品との繋がりを維持します。

## 人物を追加する

「人物を追加」で登場する作品を選び、プロフィールを入力します。
登録した人物はその作品の登場人物に加わり、人物図鑑にも表示されます。画像をまだ添付していない場合は、名前の表示を使います。

## 内容を確認して反映する

入力したら「この内容を公開サイトに反映する」にチェックを入れ、「送信内容を準備する」を押します。
次の案内に従って「GitHubで確定する」を開き、いつもの `ochikatakachio` アカウントでログインします。内容を確認し、「Create」または「Submit new issue」で確定します。その操作まではサイトは変わりません。
文章が長いときは「本文をコピー」を押し、GitHubの本文欄へ貼り付けます。本文の中の編集データを、自分で書き換える必要はありません。
画像を添付するときは、GitHubの本文欄へドラッグしてください。画像のURLは確認して取得し、元の画像形式とサイズを保って保存します。
GitHubの追加・編集依頼と、反映された内容は公開されます。公開する紹介文や裏設定だけを入力してください。作者用の操作画面そのものは公開用ファイルに含みません。

作者のアカウントが送信した依頼だけ受け付けます。パスワードやAPIキーをサイトや作者用ファイルへ入力する必要はありません。GitHubの通常のログインで確定します。
反映には数分かかる場合があります。完了後、依頼が「Closed」になり、作品一覧や人物図鑑で内容を確認できます。

## 反映できなかったとき

GitHubの「Actions」→ **Add archive work** で失敗した処理を開きます。
入力を修正した場合は元の依頼の本文を直し、「Run workflow」でその依頼の番号を指定して再実行できます。
「別の更新が入っています」と表示された場合は、作者用画面で最新データを読み込み、該当する作品や人物を選んで編集し直してください。
画像取得や入力確認が失敗した場合は、既存の公開ファイルを更新せず停止します。登録済みのURLを重複追加することもありません。
「Issues」が見えない場合は、Settings → General → Features で有効にしてください。Actionsの利用も有効にします。リポジトリの書き込み制限や `main` の保護設定がある場合は、Actionsの保存処理に影響します。

## 作品・キャラのおすすめ診断

トップの「おすすめ診断をはじめる」、または共通メニューの「おすすめ診断」から開けます。`diagnosis.html` が診断ページです。
世界観・雰囲気・相手の性格・関係性・恋愛の遊び方の5問に答えると、作品と人物をそれぞれ最大3件表示します。選んだ好みとの共通点と、作品・人物詳細へのリンクを付けています。
舞台を選んだ場合は該当するジャンル・タグの作品を候補にし、NL／BLの指定は掲載タグで確認します。BLでNL専用作品を勧めることはありません。
公開されている紹介・タグ・性格・関係から選ぶ仕組みです。裏設定や、表示を外した元の掲載プロフィールは診断に使いません。性格や運命を断定する診断ではなく、作品選びのための好みの案内です。
回答はその画面内で扱い、外部へ送信せず、保存もしません。「前の質問へ」「回答を見直す」で回答を保ったまま選び直せ、「もう一度診断する」で最初から始められます。
作品・人物を追加した場合も、新しい紹介・タグに基づいて候補に含めます。特定の作品IDを診断に固定していません。

## zetaの公開更新を自動反映する

今回の版をGitHubに上書きすると、Actionsの **Sync zeta archive** が約30分おきに動きます。毎時17分・47分を開始予定とし、zetaの公開作品紹介・タイトル・タグ・表紙・公開人物欄を確認します。新しく公開して作者ページに掲載された作品も追加候補になります。自分の公開作品だけを取り込み、ログインやAPIキーは使いません。
zetaから編集通知を直接受け取る方式ではありません。編集と同時の反映は保証できず、次の定期確認とPagesの公開処理を待ちます。GitHubの混雑等で実行が遅れたり、その回が実行されなかったりする場合があります。
初回はGitHubの **Actions → Sync zeta archive** を開き、成功した実行を確認してください。待たずに試したい場合は同じ画面の **Run workflow** を使います。作者用ファイルの「自動更新の状態を見る」からも、この画面を開けます。公開反映はこの版の作成時点では実行していません。

自動更新は、zetaの公開原文の差分を、最後に確認した原文と比較して反映します。人物の項目は明示された欄と、現在の紹介に対応する原文の位置を使います。文章構成が大きく変わって対応を確認できない項目は、元の値を維持します。非公開の内部設定を取得したり、誕生日や性格を新しく推測したりはしません。
サイト側で追加・編集した項目は、変更した項目ごとに保護して、自動更新で上書きしません。誕生日や裏設定をサイトで足しても残ります。Chacha・Plaitoonの掲載内容とリンク、独自の世界観資料も自動で書き換えません。
zetaに再び合わせたい場合は、作者用ファイルで作品・人物を選び、「zetaの公開内容に戻し、次の確認から自動更新を再開する」にチェックしてGitHubで確定してください。次の定期確認で、zetaにある公開項目と画像を取り込み直します。裏設定と、zetaに項目が存在しない追加情報は対象外です。

人物は既存IDを保って更新します。新しい人物が確認できれば追加し、確認できた掲載人物の並びを反映します。サイトだけで追加した人物は残します。zetaで非公開・削除された作品を、サイトから自動削除する処理は入れていません。
取得や画像の確認に失敗した作品は、従来のデータを維持して保留します。他の確認できた作品は反映できます。保留内容はActionsの実行ログと `assets/zeta-sync.json` の `errors` に残ります。1件も確認できなかったときは処理を止めます。
トーク数は全対象を確認できた場合だけまとめて更新し、部分的な失敗で前回の集計を新しい数値として扱いません。自動同期・作者の編集・追加は、同時に上書きしないよう同じ待ち列で実行します。
公開リポジトリでは60日間活動がないと定期実行が無効になる場合があります。止まった場合はActionsで有効にし直してください。

## 注目の物語とシリーズ

トップの表紙と注目作品は、zetaの公開トーク数が多い上位3作品です。作品一覧にもトーク数順の並び替えがあります。未集計の新しい作品は「集計待ち」、zeta未掲載の作品は順位の対象外です。
トーク数はzeta公開内容の自動同期と一緒に、約30分おきにGitHub Actionsで取得します。実行開始は遅れることがあります。取得後にPagesの更新も依頼します。編集と同時の反映ではありません。
「3.7万」のような表示は掲載元の省略表示です。厳密な個数を推測していません。同じ省略数値の場合は、取得時の掲載順を使います。
全対象を取得できなければ前回データを保ち、確認日時を表示します。48時間以上経過した場合は「更新待ち」を出します。取得に失敗した数値を0に置き換えません。

シリーズは、胡散臭い広告怪異5作品、ダサい広告怪異5作品、明影総合株式会社3作品です。トップ、シリーズ一覧、作品一覧、作品詳細から行き来できます。
作品追加・編集とトーク数更新は、同時にデータを保存しないよう順番に実行します。

公開原文の変更、既存ID保持、画像差し替え、サイト編集項目の保護、同期再開、新規作品の重複防止、失敗時のデータ保持、定期処理とPages更新を保存した公開資料で確認しています。GitHub上での実際の自動同期・反映、実ブラウザーでの見た目と作者画面の最終確認は未実施です。公開用ファイルを上書きしたあとに、作者用画面から一度確認してください。
